# ClientDeck user guide

This is the same handbook as **How to use** inside the portal. Operators should also read the root [README](../README.md) for Docker, environment, and backups.

## Studio

1. **Create the studio** — The first visitor at this URL becomes the Agency Admin and names the studio.
2. **Open a project** — Projects → New project. Name the job and the client. Round 1 is created for you.
3. **Invite people** — On the project, invite a client (required) or a project manager. Copy the link if SMTP is off.
4. **Upload work** — Add an image or a PDF (first 20 pages). New files on the same asset stack as versions.
5. **Collect feedback** — Click the image to drop a pin, write the note, then save. Resolve a thread when it is done.
6. **Ask for sign-off** — Request sign-off. The client sees Ready for you and gets email if SMTP is configured.
7. **Revise or lock** — If they request changes, upload a new version and send it back. If they approve, print the audit page.
8. **Next round** — After approval, start the next round from the signed files, or reopen the same milestone if you must edit.

Search the header for project, asset, or comment text. Archive a finished job from the project header. Restore it from the dashboard Archived list.

## Client

1. **Join the invite** — Open the link, set your name and password. You only see projects you were invited to.
2. **Review the latest files** — Open Ready for you, then each asset. Use Then / Now / Compare when there is more than one version.
3. **Leave pins** — Click the image, write what should change, save. Comments stay on that version.
4. **Send it back or sign** — Request changes with a note, or type your name and approve. Approval writes an audit record.

## Roles

- **Admin** — branding, every project, invites, archive.
- **Project manager** — assigned projects, upload, request sign-off.
- **Client** — comment, request changes, approve.

## Sign-off

Approval stores the typed name, time, IP address, browser, agreement text, a hash of that text, and the exact asset versions. Open the audit page and use Print / save PDF.

This is a formal project trail, not a certified e-sign under eIDAS or the ESIGN Act unless your counsel says otherwise.
